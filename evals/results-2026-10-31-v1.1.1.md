# Eval results — cadenceux-fms-security 1.1.1 — 2026-10-31

Correction release: FileMaker does lock file accounts. One fresh subagent per model and run,
answering the new `lockout-fact` case. Models: Claude Code's `haiku`, `sonnet` and `opus`
subagent aliases. The exact model versions behind those aliases weren't recorded by the runs,
so none is given here. The skill was loaded by path; agents were told not to run scripts,
contact hosts or read `evals/`. Graded strictly against `must` and `must_not` in `evals.json`:
one missing `must` fails the case.

The baseline said FileMaker Server has no built-in lockout and described a "Maximum failed
attempts" setting in the file's Authentication options, which doesn't exist. Both are the
error this release corrects. After the fixes no run said FileMaker has no lockout, and none
treated the lockout as protection.

## Changes made after these runs

- `references/log-review.md`: the breach test (a failing address without `NEVER-SUCCEEDED`
  signed in at some point; check when and as which account), and why a low failure count per
  account isn't reassurance, with the defences named.
- SKILL.md step 5: a low failure count or the lockout is never reassurance; say why and name
  the defences. As in 1.1.0, Haiku needed the rule in SKILL.md itself.
