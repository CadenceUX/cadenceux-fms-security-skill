# Evals: 1.4.0 against 1.3.1 (22 November 2026)

Three cases, the two new in 1.4.0 and `signed-in-before-failures`. Each ran on Haiku, Sonnet and Opus with 1.4.0,
and on Sonnet with the released 1.3.1 as the baseline: a fresh Claude Code subagent per run, told to read the
skill's SKILL.md and follow it, with no questions answered and nothing looked up online. Graded against
`evals.json`'s `must` and `must_not` facts; counts by script where a phrase settles it, read by hand otherwise.

For `several-servers-logs`, a folder held three servers' logs, two as folders and one as a .zip: one address
signed in as admin over JDBC, then failed 247 times on six names; another failed on two servers, file after file,
one of them with ordinary names. All addresses are documentation ranges and all server names are `.example`.

## What the runs show

- **Several servers.** Every 1.4.0 run ran `fms_log_sweep.py --logs`, read only its printed summary, put the
  address that signed in before its failures first as a possible compromise, named the address that reached two
  servers with a block and allow-list, and looked nothing up. The 1.3.1 baseline reached the same verdicts by running
  the single-server check on each server and reading the outputs side by side: twice the time and twice the tool
  calls on Sonnet, and the link between servers was its own inference rather than a list the script gave it.
- **File after file.** All runs called it an attack whatever the names, and said RATE was missing only because it
  went slowly. Haiku left out strong unique passwords; the 1.3.1 baseline never said to block the address.
- **Signed in first.** Every run said the order doesn't clear it and treated it as a possible compromise. Haiku
  left out closing or allow-listing port 2399. The baseline already passed this case in 1.3.1, so it guards against
  a regression rather than measuring the change.
- **Errors seen.** The 1.4.0 Sonnet several-servers answer said the attacking address kept signing in every five
  minutes, mixing it up with the server's own integration account; the summary's lines were right. No run invented
  an address or a server.

## Not measured
