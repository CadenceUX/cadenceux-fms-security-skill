# Eval results — cadenceux-fms-security 1.1.0 — 2026-10-31

Recovery readiness release. One fresh subagent per model, answering the three new cases and the
`under-attack` regression case as separate conversations; re-runs used one subagent per case.
Models: Claude Code's `haiku`, `sonnet` and `opus` subagent aliases. The exact model versions
behind those aliases weren't recorded by the runs, so none is given here. The skill was loaded
by path; agents were told not to run scripts, contact hosts or read `evals/`. Graded strictly against `must` and `must_not` in `evals.json`: one
missing `must` fails the case.

fixes 4/4 on every model. No run assumed recovery targets, treated a NAS on the server's network
as an off-network copy, or let a missing DR plan delay containment.

## Changes made after these runs

- report-format.md: an Owner column in the Recovery readiness table, and every gap is also a
  "What to fix" row with priority, owner and status.
- server-config.md and SKILL.md step 3: write each gap as a finding with a priority and an owner.
- incident-response.md, from points the Haiku and Opus runs raised: disconnect the attacker's
  open sessions (Block New Users leaves them running); check backups the server could write to
  for tampering; a file restore doesn't roll back server settings, so check Event.log for
  changes; run the file audit on restored copies.
- server-config.md, from the Haiku re-run: a timed restore should count rebuilding the server if
  it could be lost, since backups hold the hosted files, not the server's settings, schedules,
  plug-ins or certificate.
