## Description tuning

Should trigger (all matched by terms in the description): "security check my FileMaker Server",
"audit our FMS", "pen test our FileMaker server", "review these FileMaker Server logs", "were we
hit by the FileMaker attack", "harden my FileMaker Server", "is my FileMaker Server exposed to
the internet", "check Access.log for password spraying", "someone is downloading records via
the Data API", "check Guest and auto-login on our hosted files". "exposed" and
"misconfigurations" were added to the description after this check.

Near-misses (excluded by the "Not for" clause or by having no FileMaker Server security angle):
a FileMaker email-validation script, installing FMS in Docker, hardening a WordPress nginx
config, designing a privilege set for teachers, paginating Data API results.

## Changes made after this run

- client-advisories: Haiku found the general rule (CVSS 7+ is High) and the client rule (Medium) disagreed for a 7.3 Pro CVE. security-advisories.md now says client CVEs are Medium whatever their CVSS, High only on shared machines or servers.

- version-advisories: Haiku noted release-note fixes have no CVSS, so no severity band. security-advisories.md now rates them: remote code execution or authorisation bypass High, else Medium.

- file-audit-no-adt: two runs told the user to look for blank passwords in Manage > Security,
  which doesn't show them. file-security.md now says to close the gap by resetting any password
  nobody can vouch for, and to report F4 as "not verified; closed by resetting".

- SKILL.md step 2 now lists the web paths the exposure check covers, including third-party
  admin and deployment tool sign-in pages, and asks which such tools are installed.
