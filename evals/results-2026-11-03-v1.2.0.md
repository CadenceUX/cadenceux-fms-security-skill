# Eval results — cadenceux-fms-security 1.2.0 — 2026-11-03

One fresh subagent per model and run, answering the four new cases. Models: Claude Code's
`haiku`, `sonnet` and `opus` subagent aliases. The exact model versions behind those aliases
weren't recorded by the runs, so none is given here. The skill was loaded by path; agents were
told not to run scripts, contact hosts or read `evals/`. Graded strictly against `must` and
`must_not` in `evals.json`: one missing `must` fails the case. Earlier cases weren't re-run.

`php-installed` doesn't separate the skill from the baseline, which also gave folder paths from
memory. Haiku's first `signed-in-staff-typo` run left out generic accounts, so the triggers for
`POSSIBLE-COMPROMISE` went into SKILL.md step 5, and the re-run passed. As in 1.1.0 and 1.1.1,
Haiku needed the rule in SKILL.md itself.

## Script tests

- **Log check on lines in the pattern of an ODBC/JDBC attack:** `POSSIBLE-COMPROMISE`, `SIGNED-IN` with
  the account, time and connection type for a sign-in 20 minutes before the failures, the full
  account count, `XDBC`, `RATE`, and the connection in the ODBC/JDBC section.
- **Log check on five real servers' logs, about a month each:** ran without error. `SIGNED-IN` on 40
  addresses, `POSSIBLE-COMPROMISE` on 3, `RATE` on none, no ODBC/JDBC connections, and one account
  name hidden as a possible typed password.
- **Log check on made-up files:** `Event-old.log`, gzipped rotated web logs, `BEFORE-ACCESS-LOG`, a
  `.php` page and an XML path marked `ANSWERED`, and an XML record call counted.
- **Exposure check with fake responses, not a live server:** XML on and off, the PHP test page
  answering and not found, and an `X-Powered-By` header naming PHP.
- **Not tested:** the admin review's new PHP lines, and the PHP test page path against a real
  server with PHP installed.
