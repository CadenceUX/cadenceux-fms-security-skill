# Eval results — cadenceux-fms-security 1.1.2 — 2026-11-02

ODBC/JDBC release. One fresh subagent per model, answering the new `xdbc-port-2399` case.
Models: Claude Code's `haiku`, `sonnet` and `opus` subagent aliases. The exact model versions
behind those aliases weren't recorded by the runs, so none is given here. The skill was loaded
by path; agents were told not to run scripts, contact hosts or read `evals/`. Graded strictly
against `must` and `must_not` in `evals.json`: one missing `must` fails the case.

| Run | Baseline (Sonnet, no skill) | Haiku | Sonnet | Opus |
|---|---|---|---|---|
| 1. xDBC flag, log-review, exposure-check and SKILL.md changes | ✅ | ✅ | ✅ | ✅ |

The baseline already knew a web WAF doesn't see port 2399, and recommended an allow-list and a
check for successful sign-ins, so this case doesn't separate the skill from the baseline. The
release's value is in the log check itself: before 1.1.2 nothing marked a failure as having
come through 2399. With the skill, all three models also weighed the failures (High from an
unknown address, a stale password from a known BI tool), tied them to the lockout, and named
the verdict and its log-coverage limit; the baseline did none of those.

The `XDBC` flag was tested on sample Event.log lines in the `[fmxdbc]` form. No real ODBC/JDBC
failure line was available.
